# v0.3 — Firefighter responder & multi-fleet comparison

This release adds the first **responder agent** to the SoCal wildfire / power-grid
testbed and the analysis machinery to compare *how many* aerial firefighting
assets are deployed. It culminates in a single palaestrAI experiment that runs the
**same Eaton-Canyon fine-grid scenario three times** — no firefighters, a small
fleet, and a large fleet — and renders them side by side.

## 1. What's new

### Firefighter Agent (aero tanker responder)

`palaestrai_socal/agents/firefighter_agent.py` (`FirefighterMuscle`) is a scripted
fleet of `n_planes` Large Air Tankers that lay a long-term retardant firebreak
ahead of the fire head. Each step it reads the same-step fire field
(`gis.cell_state` + `gis.fuel_class`) and writes
`(row, col, SUPPRESSED, LAYER_SUPPRESSION)` edits through the existing
`gis.cell_mutations` actuator. The GIS environment arbitrates the wildfire's and
the firefighter's edits by fixed priority — `BURNED_OUT > SUPPRESSED > BURNING >
UNBURNED`, turn-order independent — and ages a retardant line back to `UNBURNED`
after `SUPPRESS_PERSIST_STEPS` steps.

- **One knob, `n_planes`.** All productivity / wind constants live in
  `palaestrai_socal/agents/firefighter_core.py`. In wind `≥ 18 m/s` the fleet is
  **grounded** (budget 0, zero edits), so the high-wind Eaton 25 m/s run is
  unchanged.
- **True no-op when absent.** With zero SUPPRESSED cells the fire CA is
  bit-for-bit identical to v0.2 (regressed in `tests/test_suppression_block.py`).

### Multi-fleet comparison experiment

`palaestrai_socal/experiment_eaton_local_ab.yml` runs the **same fine-grid
scenario three times in one store** with an identical seed (47):

| Phase | uid | `n_planes` | Role |
|-------|-----|-----------:|------|
| 0 | `phase_0_no_ff`    | 0 | Baseline (no firefighters) |
| 1 | `phase_1_with_ff`  | 3 | Small fleet (3 aero tankers) |
| 2 | `phase_2_with_ff7` | 7 | Large fleet (7 aero tankers) |

All phases share the exact scenario: bounds around the Eaton Canyon ignition
(≈50 m raster, 222×184), wind 8 m/s @ 45°, 60 steps (2.5 simulated days),
turn order `wildfire → firefighter → damage_mapper → grid_probe`. Phases run
**sequentially**, so peak memory equals a single-phase run (~5 GB).

### Phase-aware, N-phase analysis

- `analysis/store_readers.py` — `read_run(..., phase_uid=…/phase_index=…)` and
  `list_phases(store)`; per-step snapshots carry `vmin_pu`, `vmean_pu`,
  `intertie_mw`, `load_mw`, plus `meta["intertie_is_proxy"]`.
- `analysis/make_comparison_timelapse.py` — **generalised to N phases.** Stacks
  one map row per phase on the left and four shared metric panels on the right
  (SAIDI, bus voltage, served power, intertie flow), one line per phase. Each
  firefighter row shows fading plane icons (✈) at the active drop locations and a
  per-phase HUD (Day / Wind / Retardant-cell count); the baseline shows Day/Wind
  only. A backward-compatible shim keeps the old 2-phase
  `render_comparison(snaps_a, meta_a, snaps_b, meta_b, …)` call working.
- `analysis/grid_metrics_report.py` — **N-way static PNG** via `build_figure_n()`.
  One SAIDI / served-MW / intertie line per phase, plus min (dashed) and mean
  (solid) voltage per phase, with a banner of final burned acres and acres saved
  versus the baseline. The original 2-phase `build_figure()` is retained.

## 2. Headline result — fleet size scales suppression

Running the three phases of `experiment_eaton_local_ab.yml` on the fine-grid
Eaton scenario (seed 47, real line-flow sensors, `intertie_is_proxy = False`):

| Phase | Burned area | Acres saved vs baseline | Final SAIDI |
|-------|------------:|------------------------:|------------:|
| No firefighters | 18,743 ac | — (baseline) | 1.98 |
| 3 aero tankers  | 18,606 ac | 137 ac (~0.7 %) | 1.93 |
| 7 aero tankers  | 18,449 ac | **294 ac (~1.6 %)** | **1.84** |

Going from 3 to 7 tankers **more than doubles the acres saved** and produces the
largest SAIDI reduction. This is consistent with the design thesis that scripted
aerial firefighting *delays and constrains* the front rather than extinguishing
it — so adding aircraft compounds the firebreak effect. Bus voltage stays stable
(min ≈ 0.94 p.u.) across all three phases; the larger fleet retains marginally
more served load.

## 3. Reproduce

```bash
# 1. run the 3-phase experiment (heavy; ~5 GB peak, phases run sequentially)
env PYTHONPATH=$PWD palaestrai -c runtime_pg_eaton.conf.yaml start \
  palaestrai_socal/experiment_eaton_local_ab.yml

# 2. 3-row comparison timelapse (no-FF / 3 tankers / 7 tankers)
python analysis/make_comparison_timelapse.py \
  --store <store-uri> \
  --phases phase_0_no_ff:0,phase_1_with_ff:3,phase_2_with_ff7:7 \
  --stride 1 --fps 10 --outdir analysis

# 3. N-way static grid-metrics PNG (SAIDI, voltage, power, intertie)
python analysis/grid_metrics_report.py \
  --store <store-uri> \
  --phases phase_0_no_ff:0,phase_1_with_ff:3,phase_2_with_ff7:7 \
  --out analysis/grid_metrics_ab.png
```

The `--phases` value is a comma list of `phase_uid` or `phase_uid:n_planes`
(the plane count is inferred from the uid when omitted). The legacy
`--phase-a/--phase-b` 2-phase flags still work on both scripts.

> `intertie_mw` is a real sum of stored `*-line-*.p_from_mw` flows when those
> sensors are present in the store, else a clearly-labelled served-load proxy
> (`meta["intertie_is_proxy"]`).

## 4. Tests

`pytest -m "not slow"` covers the new machinery: the phase reader, the
N-phase grid-metrics figure (`build_figure_n` plus the retained `build_figure`),
the comparison-timelapse render (including the 2-phase back-compat shim), and the
suppression no-op regression. 103 tests pass.

## 5. Known non-fatal issue

The firefighter muscle returns a telemetry **dict** as `data_from_muscle`
(`planes_in_service`, `drops_this_step`, `retardant_cells`, …). palaestrAI's
dummy-brain learner attempts `data_from_muscle + 1` and logs a
`TypeError: unsupported operand type(s) for +: 'dict' and 'int'` once per
firefighter turn. This is **non-fatal** — the brain does not drive output; all
grid mutations come from the muscle's actuator writes — and does not affect any
result above.
