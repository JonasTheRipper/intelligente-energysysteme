# v0.4 — Full-Blown Firefighting

**Released 2026-06-28.** Extends the v0.3 aero-tanker responder into a deterministic,
scripted **multi-resource incident-command** model. Implements roadmap steps 1–7 of
[`docs/DESIGN_firefighting_actions.md`](DESIGN_firefighting_actions.md); step 8 (a
learning brain) is deliberately **not** implemented — everything stays scripted
(palaestrAI dummy brain + dummy objective; only the muscle is custom) and numpy-only
in the `*_core` / `firefighting` logic.

For the *why* and the full design rationale, read the design document. This file is
the **release summary**; the operational how-to ("run it, change it, read the
results") lives in [`docs/RUNNING_THE_EXPERIMENT.md`](RUNNING_THE_EXPERIMENT.md).

---

## 1. What's new

### 1.1 `firefighting/` package
A new sub-package, `palaestrai_socal/agents/firefighting/`, holds all the new
incident-command logic. It is pure numpy and has **no palaestrAI dependency** — the
agent muscle (`firefighter_agent.py`) remains the single palaestrAI touch-point and
simply delegates to it.

| Module | Responsibility |
|---|---|
| `resources.py` | One frozen dataclass per resource type (`TankerFleet`, `HeloFleet`, `HandCrews`, `Dozers`, `Engines`). Each exposes `capacity(wind_speed, step_min, cell_m, slope_deg=0.0) -> int` (a per-step line/point budget). `build_resources(...)` assembles a fleet from counts. |
| `tactics.py` | numpy-only geometry primitives: `indirect_line` (wraps v0.3 `select_retardant_line`), `direct_attack`, `containment_line` = `handline` = `dozer_line`, `burnout`, `point_protect`. |
| `doctrine.py` | `fireline_intensity` proxy, `choose_attack` (direct vs indirect), `is_anchored` / `anchor_and_flank_order`. |
| `planner.py` | `IncidentCommand.propose(...) -> List[(row, col, state, layer)]` (the merged action list) and `value_raster_from_buses(...)` (inverse of the DamageMapper bus→cell map). |

### 1.2 Resource model (documented constants, the only knobs are counts)
Every productivity / constraint figure is a **documented module constant**; per
[design §8](DESIGN_firefighting_actions.md) the only operational knobs are the
resource *counts*.

| Resource | Productivity | Wind behaviour | State laid |
|---|---|---|---|
| **TankerFleet** | delegates verbatim to `firefighter_core.retardant_budget` (v0.3 exactness) | grounds at `GROUND_WIND_MS = 18 m/s` | `SUPPRESSED` |
| **HeloFleet** | `HELO_DROPS_PER_HOUR = 8`, `HELO_LINE_KM_PER_DROP = 0.25` | degrades above `16 m/s`, grounds at `22 m/s` (higher than tankers) | `SUPPRESSED` |
| **HandCrews** | `CREW_LINE_M_PER_HOUR = 90`, slope half/cutoff `30°/45°` | never wind-grounded | `CONTAINED` |
| **Dozers** | `DOZER_LINE_M_PER_HOUR = 400`, slope half/cutoff `20°/35°` | never wind-grounded | `CONTAINED` |
| **Engines** | `ENGINE_ASSETS_PER_HOUR = 1.5` (a point count, not a line) | n/a | `CONTAINED` (point protection) |

### 1.3 New `CONTAINED` cell state (= 5)
A completed **ground line** (hand crew / dozer) or a **protected point** (engine) is
durable in a way that an in-progress retardant drop is not, so it gets its own state.

- `CONTAINED = 5`, inserted in the priority order **strictly between** `SUPPRESSED`
  and the terminal `BURNED_OUT`:
  `STATE_PRIORITY = {UNBURNED:0, BURNING:1, FLOODED:2, SUPPRESSED:3, CONTAINED:4, BURNED_OUT:5}`.
  All values are distinct → arbitration is **total and tie-free**.
- A non-ignitable guard in `wildfire_cma/cma.py` mirrors the `SUPPRESSED` guard
  (placed before any RNG draw, so absent a CONTAINED cell the CA spread is
  **bit-for-bit v0.2**).
- CONTAINED does **not** age out within an episode (`age_suppressed` only touches
  `SUPPRESSED`).

### 1.4 Grid coupling (point protection)
When `protect_assets: true`, the muscle builds a per-cell **grid-asset value raster**
(the inverse of the DamageMapper bus→cell registration) and the engine fleet does
point protection of the highest-value grid-critical cells, marking them `CONTAINED`
(non-ignitable). No new grid actuator is introduced; the protection is expressed
through the existing GIS cell-mutation channel. Degrades to a graceful no-op when
pandapower / the grid JSON are unavailable.

### 1.5 Telemetry fix
v0.3 returned a telemetry **dict** on the brain/data channel, making palaestrAI's
`DummyBrain` attempt `dict + int` every turn (a non-fatal `TypeError` logged each
step). v0.4 returns **`None`** on that channel; telemetry lives on
`self._last_telemetry`. Resource positions remain reconstructable from the stored
`SUPPRESSED`/`CONTAINED` cell-state diff (`analysis/plane_icons.py`). The run logs
are now clean of that warning.

### 1.6 Renderer enhancements
- **Per-tactic colours** in `make_comparison_timelapse.py`: retardant pink
  (`SUPPRESSED`) vs ground-line brown (`CONTAINED`); the HUD shows ground-line cell
  counts when present.
- **Descriptive phase labels.** Both renderers previously labelled phases by plane
  count only, which collapsed every multi-resource phase to "3 planes". They now
  honour an optional caller-supplied label. The `--phases` CLI grammar is extended,
  **fully back-compatible**:

  ```
  uid                       # plane count inferred from uid
  uid:n_planes              # v0.3 syntax, still works
  uid:n_planes:Label text   # NEW — descriptive label (no commas; ':' separates)
  ```

- **Headline KPI** in `grid_metrics_report.py` `build_figure_n`: **MW preserved /
  SAIDI avoided per resource-hour** (reported per tanker-hour, the only fleet count
  the store exposes per phase — see "Deviations").

## 2. The v0.4 experiment

`palaestrai_socal/experiment_eaton_firefighting.yml`
(uid `socal_v04_eaton_firefighting`, seed 47, 222×184 fine-grid Eaton scenario,

## 3. Results (seed-47 fine-grid Eaton, 4 phases, `EXIT_RC = 0`)

| Phase | Burned (final) | SAIDI (final) | Notes |
|---|---|---|---|
| No firefighting | 18,743 ac | 1.97 | baseline |
| Air only (3 tankers) | 18,606 ac (saved 137) | 1.93 | reproduces v0.3 |
| Air + ground (3T / 4 crew / 2 dozer) | 18,378 ac (saved 365) | 1.92 | ground line cuts more area |
| Full triage (+ 3 engines, point protect) | 18,089 ac (saved 654) | **0.27** | dramatic grid-reliability win |

**Headline finding:** point protection of grid-critical cells in the full-triage
phase keeps SAIDI near **0.27** (vs ~1.97 baseline) and holds ~20 MW more load
energised — a far larger *grid* benefit than the acreage saved alone would suggest.
This is the core argument for the testbed: a firefighting tactic that barely changes
total burned area can still be decisive for grid resilience if it protects the right
cells.

## 5. Design deviations (documented, intentional)

- **Telemetry not re-exposed as a GIS sensor.** A muscle cannot register new env
  sensors, so per-step telemetry stays on `self._last_telemetry`; resource positions
  remain reconstructable from the stored cell-state diff.
- **MW/SAIDI-per-resource-hour KPI uses the plane count** as the denominator,
  because that is the only fleet count the store exposes per phase (ground counts are
  not persisted). Reported honestly as "per tanker-hour".
- **Air + ground line overlap → CONTAINED.** When tankers and ground resources lay
  line on the same ahead-of-head geometry, the higher-priority `CONTAINED` state wins
  the merge. This follows the documented arbitration priority; it is not a special
  case. Consequence: the per-tactic colour mix only shows both states where the lines
  do **not** overlap.
